## Pontos técnicos (resumo em português)

- Contexto histórico: Lukas Tönne trabalhou na simulação de cabelo/sistema de partículas no projeto "Cosmos Laundromat" (~2014-2015); voltou ao Blender Institute em 2023 e retomou o tema de simulação de cabelo em 2025, agora usando Geometry Nodes.
- Motivo da substituição: o sistema antigo de partículas está em modo de manutenção há ~10 anos e mudou muito pouco (comparação Blender 2.75 vs. Blender 5.0); é "spaghetti code" com muitas interdependências, difícil de modificar sem quebrar outras partes.
- Problema de dados do sistema antigo: partículas viram curvas ao crescer da malha; essas curvas viram uma malha (mesh); essa malha é simulada como pano (cloth simulation); o resultado volta para curvas/partículas — várias representações de dados coexistindo ao mesmo tempo, gerando confusão e fragilidade.
- Problema físico do método antigo: simular cabelo como cloth (malhas de aresta, sem faces) é instável e não captura energia de torção ("twist energy"), podendo adicionar/remover energia de forma não-física.
- Nova base técnica: "Hair Curves" (novo tipo de dado de curvas) totalmente integradas a Geometry Nodes, com suporte a atributos — permite mover dados de simulação sem estruturas de dados dedicadas como as do sistema de partículas.
- Novo recurso de Geometry Nodes usado: "Simulation Zone", que permite iteração (loop) dentro de um modifier de Geometry Nodes — antes disso, Geometry Nodes não suportava iteração nativa.
- Modelo físico escolhido: "Cosserat rods" (hastes de Cosserat) — otimização para hastes finas descritas só pela linha central, mais um atributo de rotação (necessário para capturar a energia de torção, diferente de uma simulação de pano comum).
- Tipos de restrições (constraints) do solver: Stretch (o cabelo não pode mudar de comprimento significativamente — pode ser mais "soft" em cabelo cacheado), Bending (mantém a forma relativa entre segmentos — mais rígida em cabelo "arame"), Dynamic/Root (prende a raiz do cabelo à cabeça, atualizada a cada frame conforme a animação), Collision (detectada a cada frame, empurra o cabelo para fora da superfície do colisor).
- Método de solver: XPBD (Extended Position-Based Dynamics), técnica padrão desde ~2015 (PBD "clássico" desde ~2011), combinado com o modelo de Cosserat rods (referência a um paper específico citado na talk). Rotações usam quatérnions, que precisam permanecer na esfera unitária — mais propenso a erros numéricos que posições puras.
- Cada passo de simulação subdivide o timestep (de ~1/24s para algo como 60-120 fps) para estabilidade, depois aplica dinâmica Newtoniana não restrita (posição/velocidade/rotação/velocidade angular) e só então resolve as restrições (constraint solving) dentro de uma "repeat zone" pelo número de substeps escolhido.
- Uso do recurso "Closure" (novo em Geometry Nodes): permite definir parte da árvore de nodes fora do node group onde é usada, possibilitando que o node group do solver contenha toda a física mas exponha partes editáveis pelo usuário (ex.: gravidade custom) sem ficar preso dentro do node group.
- Histórico de 3 protótipos: (1) tudo em node groups puros — fácil de prototipar/editável, mas difícil de revisar em code review, sem diff de node groups, matemática fica verbosa, bugs com assets duplicados; (2) solver inteiro em um único node C++ — rápido e simples de montar, mas vira "caixa preta" não editável; (3) solução atual — "declarative behaviors" / "world components" e depois "typed bundles": bundles tipados (com um campo de tipo/string) que se auto-preenchem com os sockets certos (geometria, massa por ponto, rotação opcional etc.) via botão de "sync", permitindo aninhar bundles dentro de bundles para montar hierarquias do "mundo" da simulação.
- Bundles disponíveis incluem: geometria simulada (chamada por enquanto de "XPBD geometry"), forças (forces), constraints de haste (rod constraints, específicas para cabelo), constraints genéricas (damping, gravidade etc.).
- Testes de integração com outros motores de física: Bullet (atual no Blender), Jolt (engine de rigid body candidata a substituir o Bullet) e Box2D (teste simples); todos funcionaram com os mesmos bundles declarativos do solver soft-body. Testou-se também usar a detecção de colisão do Jolt para gerar contatos usados pelo solver de cabelo (colisão atual do Blender é básica, só para colisores rígidos/convexos).
- Problemas conhecidos no estado atual (demonstrados em um "blooper reel"): cabelo "explode" no início por já estar penetrando o colisor (ferramentas de grooming não garantem que fique fora da malha); jitter de colisão (pontos de contato surgindo/sumindo); falta total de autocolisão do cabelo (por isso o artista precisou deixar o cabelo mais rígido do que deveria, para compensar a falta de volume); falta de fricção entre fios (fios "deslizam" de forma não natural); geração de cabelo interpolado (rendered hairs) a cada frame é cara e instável quando a malha-guia estica — solução proposta: gerar o cabelo renderizado uma vez e só transferir o movimento das guias depois (já testado, mas não incluído nos assets oficiais ainda).
- Trabalho futuro citado: visualização de forças internas do solver para os artistas (evitar o erro comum, visto em Cosmos Laundromat, de aumentar a rigidez das constraints demais até o sistema ficar instável); métodos alternativos de solver mais rápidos ("Vertex Block Descent" e "solvers globais"); autocolisão via método tipo "material point method" (converter pontos em uma grade/grid, gerar forças de pressão e fricção); "hair rest shape" — um solver reverso para achar a forma de repouso sem gravidade, evitando que o cabelo "murche" assim que a simulação liga (hoje os artistas modelam o cabelo já "pensando" na gravidade, o que causa esse efeito).
- Falta de suporte a deformação por armature (esqueleto) em curves dentro de Geometry Nodes: contorno atual usado por artistas é gerar fitas/ribbons de malha a partir das curvas, animar essas fitas e transferir o movimento de volta para as curvas — fluxo trabalhoso que exige três objetos diferentes para o mesmo personagem; há branches experimentais para resolver isso nativamente.
- Meta de lançamento (na época da talk, set/2025): esperança de algo em Blender 5.0, mais provável em 5.1 (mesmo como feature experimental).
- Q&A: parâmetros do solver (substeps etc.) são editáveis por serem baseados em nodes; hair cards para games são viáveis mas provavelmente exigem simplificar a simulação; ao editar a topologia do cabelo durante a simulação, o estado do solver pode ser invalidado e reiniciado do zero (velocidade zero), mas reposicionar/subdividir guias sem adicionar novos fios deve funcionar; interação entre simulação de cabelo e outros solvers (fluidos, rígidos) é mais simples quando é "de mão única" (output de um vira input do outro) — Jolt já suporta soft bodies e pode ganhar suporte a Cosserat rods; não há decisão ainda sobre como objetos tipo "force field" vão alimentar o sistema de bundles fora de Geometry Nodes; ainda não há um "Rigify para cabelo" nem suporte a armature nativo em Geometry Nodes; para animação guiada por mão (guide hairs animados), a estratégia mais simples cogitada é dividir guias entre um grupo animado e outro simulado.
